🔒 Rapport de Sécurité — Pulse Santé

Ce document détaille les mesures de sécurité implémentées sur le site Pulse Santé pour protéger les données des utilisateurs et prévenir les attaques courantes.

Dernière mise à jour : 31 mars 2026

🖥️ Sécurité Serveur (.htaccess)

Configuration des en-têtes de sécurité HTTP
HSTS activé (force HTTPS pendant 1 an)
Prévention du clickjacking (X-Frame-Options: SAMEORIGIN)
Prévention du MIME sniffing (X-Content-Type-Options: nosniff)
Protection XSS héritage (X-XSS-Protection)
Politique Referrer stricte
Permissions-Policy restrictive (géolocalisation, caméra, micro désactivés)
Blocage des fichiers sensibles (.env, .git, config)
Compression GZIP pour les assets
Cache avec expiration intelligente
Blocage des attaques SQL Injection et XSS basiques
Protection contre le hotlinking

🛡️ Content Security Policy (CSP)

Directive Valeur Raison
default-src 'self' Autorise uniquement les ressources du même domaine par défaut
script-src 'self' + CDN fiables Prévient l'injection de scripts malveillants
style-src 'self' + 'unsafe-inline' Permet les styles inline (nécessaires pour le design)
form-action 'self' Les formulaires ne peuvent être soumis qu'au même domaine
frame-ancestors 'self' Le site ne peut être embédé que par lui-même

📝 Validation des Formulaires

Validation côté client (email, téléphone, longueur)
Sanitization de tous les inputs
Vérification du format email (regex)
Vérification du format téléphone
Limitation de la taille du message (1000 caractères max)
Échappement XSS des données avant envoi
Token CSRF généré au runtime
Gestion d'erreurs sécurisée (sans exposer d'infos internes)

📦 Dépendances Externes avec SRI (Subresource Integrity)

Google Fonts (sans SRI requis, domaine fiable)
EmailJS v4 avec hash SRI validé
Toutes les ressources en HTTPS
Crossorigin=\"anonymous\" pour les ressources tierces

Clés publiques : Seule la clé publique EmailJS est exposée (sans risque). Les secrets restent côté serveur.

🔐 Protection des Données (FormEmail)

Les données sont envoyées via EmailJS (service tiers sécurisé)
HTTPS obligatoire pour toutes les transmissions
Aucune données sensible n'est stockée en client
Validation complète avant envoi
RGPD conforme (collecte consentie, droit d'accès)

⚡ Recommandations pour Production

Configurer un WAF (Web Application Firewall)
Activer le monitoring et les logs de sécurité
Implémenter reCAPTCHA sur les formulaires
Mettre en place un système de rate-limiting
Utiliser un service de gestion des secrets (HashiCorp Vault)
Auditer régulièrement les dépendances (npm audit)
Faire des backups réguliers
Implémenter un monitoring et alertes
Certificat SSL/TLS à jour et auto-renouvelé
Tester aux vulnérabilités OWASP Top 10
